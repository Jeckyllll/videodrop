# VideoDrop на сервере — предварительная версия 2.0

Отдельный Telegram-бот, постоянная очередь SQLite, журнал заданий и ограниченное временное хранилище. Hermes не требуется для обработки файлов. Локальная версия 1.5.2 продолжает работать отдельно.

## Сценарии

- Пользователь нажимает `/start`; владелец получает кнопки допуска/отказа. Авторизация привязана к Telegram ID.
- Видео сначала скачивается на сервер, затем в Telegram появляются «Получить ссылку» / «Получить файл». В сообщении указан фактический размер. При изменении качества или формата после скачивания файл скачивается заново по явному выбору пользователя.
- «Получить ссылку» для владельца и допущенных сотрудников всегда означает загрузку в подключённый YouTube-канал с доступом `unlisted`. Серверная ссылка на скачивание никогда не подменяет этот вариант. Сотрудник получает ссылку на конкретный ролик, без доступа к настройкам или OAuth канала.
- «Получить файл» в Telegram: документ без повторного кодирования, если он проходит по размеру; иначе прямая HTTPS-ссылка на скачивание файла с сервера, действующая 24 часа. Рабочий предел обычного Bot API — 45 MiB. Качество не снижается для попадания в лимит.
- Для задания из расширения способ получения выбирается до отправки: `mode=link` для YouTube, `mode=file` для прямой ссылки на скачивание независимо от размера. Сервер сам выставляет `entrypoint=extension` для API-заданий. `GET /api/jobs/<id>` возвращает статус и готовые ссылки владельцу задания; чтение результата не продлевает хранение.
- Посты Instagram `/p/` и TikTok `/photo/`: только картинки в исходном порядке, без текста поста. В боте они отправляются файлами, без выбора YouTube.
- Без настроенного HTTPS большой файл и файл из расширения не выдаются по прямой ссылке: бот сообщает причину и сохраняет готовый файл на 24 часа. YouTube также требует отдельного подключения. Эти внешние подключения пока не завершены.
- При отправке нескольких изображений сохраняется прогресс по файлам. В случае неопределённого ответа повторная отправка автоматически не производится.

## Журнал и роли

`/history` — свои задания. `/audit` — последние задания сотрудников. `/audit TELEGRAM_ID` — конкретный сотрудник. `/users` — допуск/отключение. `/export` — CSV всех заданий. `/status` — очередь и объём хранения.

Журнал содержит время, Telegram ID, имя/username, ссылку на источник без секретных query-параметров, название, формат, разрешение, выбранный способ выдачи, размер и результат. События: запрос, готовность файла, доставка в Telegram, подтверждение YouTube, запрос скачивания файла, отмена и удаление по сроку. Доставка не означает просмотр ролика. Бот заранее сообщает пользователям о журнале. Личные чаты и прочие действия сотрудников не читаются.

Куки источников зашифрованы, передаются в дочерний процесс через stdin и удаляются из очереди после завершения/ошибки. OAuth-токен YouTube зашифрован, принадлежит только серверу. В журнал, экспорт и ответы API секреты не попадают.

## Хранение и восстановление

Один тяжёлый процесс; не больше 20 активных заданий суммарно и 3 на человека. Общий бюджет 20 GiB, одно задание до 8 GiB, резерв свободного места 2 GiB. Лимиты проверяются во время скачивания. Временный файл по ссылке — 24 часа с момента выдачи ссылки; ошибка доставки и ожидание выбора — также 24 часа. После подтверждённой доставки в Telegram файл удаляется. После YouTube — только после проверки канала, доступа `unlisted`, завершения обработки и отправки ссылки пользователю.

Ссылка перестаёт работать по истечении срока. Очистка файлов запускается каждые 30 секунд независимо от долгих скачиваний и загрузок; чтение результата не продлевает срок.

После перезапуска скачивание возобновляется новым запуском в своей папке. Отправка, которая могла уже завершиться, переводится в «Нужна проверка», чтобы не создать дубликат. Автоматический повтор публикации не выполняется. Метаданные журнала остаются после удаления медиа.

## Установка

1. Скопировать исходники в отдельный каталог `/srv/apps/videodrop`.
2. Создать `server/.env` по `.env.example`, указать ID владельца и токен **отдельного** бота. Токен Hermes не использовать.
3. `server/data` должен принадлежать UID/GID `10001:10001`, права `700`. `.env` — `600`.
4. От root установить `server/network-guard.sh` в `/usr/local/sbin/videodrop-network-guard`, а `server/videodrop-network-guard.service` — в `/etc/systemd/system/`. Выполнить `systemctl daemon-reload` и `systemctl enable --now videodrop-network-guard`. Он ограничивает только мост `br-videodrop`, блокируя обращения контейнера к внутренним сетям и хосту.
5. `docker compose -f server/compose.yaml up -d --build`.
6. Проверить `curl http://127.0.0.1:8787/health`. Поля `telegramConfigured`, `telegramConnected`, `youtubeConnected` различают установленный процесс и подключённые сервисы.

Сейчас режим Telegram-only: порт публикуется только на `127.0.0.1:8787`, публичные API, выдача файлов по HTTP и OAuth callback отключены. Не открывать наружу HTTP-порт и не передавать через него токены/куки. Для расширения позже нужен HTTPS и `VIDEODROP_PUBLIC_URL`.

## YouTube

Требуется Google Cloud проект, YouTube Data API и OAuth-клиент. Личный Google-аккаунт подходит. Для режима только Telegram создать OAuth-клиент типа Desktop app и выполнить на компьютере `.venv/bin/python scripts/connect_server_youtube.py --client /absolute/path/client.json --host contabo-main`. Скрипт сохраняет адрес входа во временный файл `.server-state/youtube-authorization-url.txt`; открыть его в браузере, выбрать канал и дать разрешение. Локальный callback принимает ответ Google, проверяет канал и сохраняет зашифрованное разрешение на сервер через SSH. После этого компьютер не нужен. Адрес входа автоматически удаляется; токены не печатаются.

Для будущего веб-подключения клиентский JSON типа Web сохраняется только в `server/data/youtube-client.json`, callback — `https://YOUR-HOST/oauth/callback`. `/youtube` выдаёт одноразовый адрес входа на 10 минут.

Запрашиваются `youtube.upload` и `youtube.readonly`: загрузка и проверка результата/канала. Каждая отправка явно устанавливает `unlisted` и `notifySubscribers=false`. Ролики считаются не предназначенными для детей. Сначала нужен тест на реально подключённом канале; доступ `unlisted` нельзя считать подтверждённым по наличию кода.

## Проверка

`.venv/bin/python -m unittest discover -s tests -p 'test_server.py' -v`

Проверяются разделение пользователей, запрет администрирования сотрудникам, шифрование и редактирование секретов, одноразовая привязка, отмена/истечение срока, сохранение файлов при ошибке, отсутствие повторной публикации после рестарта и закрытость HTTP в Telegram-only режиме. Это не заменяет реальную проверку Telegram и YouTube с подключёнными аккаунтами.
