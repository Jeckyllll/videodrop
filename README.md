# VideoDrop

Простое локальное приложение для macOS: ссылка → разрешение → формат → скачать.

## Запуск

Дважды откройте **Запустить VideoDrop.command**. В Chrome откроется http://127.0.0.1:8765.
При первом запуске зависимости устанавливаются в `.venv` рядом с приложением.
На этом Mac они уже подготовлены. Нужен Python 3.10+; для YouTube также Node.js 22+ или Deno.

1. Вставьте ссылку на видео и нажмите **Найти видео**.
2. Выберите доступное разрешение и MP4, MKV, MP3 или M4A.
3. Нажмите **Скачать**. Готовые файлы лежат в папке **Загрузки** рядом с приложением. Кнопка в окне откроет её.
4. Нажмите **Открыть видео** на карточке готовой загрузки — файл запустится в стандартном плеере Mac. Для MP3/M4A кнопка называется **Открыть аудио**. После отправки появится **Открыть на YouTube**; ссылка останется доступной и после удаления локальной копии.

Видео скачивается в исходном качестве не выше выбранного разрешения; звук добавляется автоматически, когда источник его предоставляет. MP4/MKV — контейнеры: кодеки остаются исходными. Для MP3 используется 192 кбит/с. M4A сохраняет AAC без повторного кодирования, когда он доступен.
Скачивания выполняются по очереди. Вкладку можно закрыть. Перезапуск Mac останавливает текущую очередь; история готовых файлов и отправок сохраняется локально. Отмена удаляет временные файлы конкретной задачи.

## Кнопка в Chrome

После первого запуска приложения:

1. Откройте `chrome://extensions` и включите **Режим разработчика**.
2. **Загрузить распакованное расширение** → выберите папку `extension` из этого проекта.
3. Закрепите VideoDrop на панели Chrome.

Откройте страницу урока → VideoDrop → **Выбрать** возле нужного плеера. Приложение покажет качество.
В RMES на проверенной странице были три Vimeo-плеера: каждая часть выбирается отдельно.

Если источник требует авторизации, отметьте **Передать доступ к этому сайту**. Chrome запросит доступ к cookies и доменам страницы/выбранного видео. Приложение получает только cookies этих адресов, хранит их в памяти и использует для обращения к источнику. Пароли вводить в VideoDrop не нужно.

Для плееров с `blob:` и динамическими HLS/DASH-потоками нажмите **Найти потоки на странице**. Эта функция отдельно запрашивает доступ к сайтам, потому что видео может лежать на неизвестном CDN. Наблюдение работает только во вкладке, где нажата кнопка, не более 30 минут. Страница перезагрузится; запустите видео и снова откройте расширение. Список очищается при переходе на другой адрес/закрытии вкладки; разрешения можно отозвать в настройках Chrome.

## YouTube через Chrome — версия 1.3

Загрузка работает через обычный YouTube Studio в Chrome. Google Cloud, OAuth-клиент и API-ключи больше не используются.

### Один раз после обновления

1. Откройте `chrome://extensions`, найдите **VideoDrop** и нажмите **Обновить / ↻**. Если Chrome попросит новые разрешения, подтвердите **«Отладчик»**. Нужен Chrome 120 или новее.
2. Откройте расширение VideoDrop, затем локальное приложение. Включите **Загружать на YouTube** и нажмите **Подключить Chrome**.
3. В открывшейся вкладке Studio войдите в свой YouTube-аккаунт, если требуется. VideoDrop запомнит канал, показанный в этом профиле Chrome. Для смены канала сначала переключите его в Studio, затем нажмите **Сменить канал** в VideoDrop.

Расширение проверяет очередь каждые 30 секунд. Когда расширение уже на связи, кнопка приложения будит его сразу. Если написано, что расширение не отвечает, откройте его окно в Chrome.

### Две галочки

- **Загружать на YouTube** — скачать выбранный MP4/MKV и отправить через отдельную вкладку Studio. Название берётся из скачанного видео, аудитория — из настройки рядом с галочкой. Доступ явно выбирается **«По ссылке»** при каждой отправке.
- **Удалить локальную копию после загрузки** — выключена по умолчанию. Файл удаляется только после чтения сохранённой страницы ролика: правильный канал и исходное имя файла, доступ «По ссылке», завершение обработки всех показанных вариантов качества. Дополнительно проверяется, что локальный файл не изменился. При смене канала или выключении первой галочки удаление сбрасывается.

MP3/M4A сохраняются только на Mac — для них снимите галочку YouTube.

Во время отправки оставьте Chrome, приложение и созданную вкладку Studio открытыми; не переводите Mac в сон. Не закрывайте уведомление Chrome об отладке этой вкладки: оно остановит управление. Разрешение «Отладчик» технически широкое, но код VideoDrop подключается только к новой вкладке Studio, которую сам создал для вашего задания. Он не подключается к другим открытым вкладкам. Файл читается Chrome прямо с диска, без второй копии и без загрузки целого файла в память расширения. Пароли и cookies Google остаются в Chrome.

### Результат и восстановление

**Открыть видео** запускает сохранённый файл на Mac. **Открыть на YouTube** появляется после получения ссылки и остаётся после удаления локальной копии. **Открыть YouTube Studio** позволяет проверить незавершённую отправку.

История скачанных файлов и известные ссылки YouTube сохраняются на Mac и восстанавливаются после перезапуска. Если ссылка уже получена, **Проверить YouTube** открывает страницу существующего ролика и проверяет её; повторной загрузки файла не будет. Если файл уже передан, но Studio не успел показать ссылку, автоматический повтор запрещён, чтобы не создать дубликат. В этом случае проверьте Studio вручную.

При запросе входа, изменении интерфейса, закрытии вкладки, недоступном канале или ошибке локальная копия остаётся. Вкладка с ошибкой остаётся открытой для проверки; сама загрузка YouTube может продолжиться в ней. Кнопка **Отменить** останавливает управление и закрывает только созданную для задания вкладку, но не удаляет уже отправленный ролик из YouTube. Обработка ожидается до 4 часов, передача — до 24 часов; затем остаётся возможность проверить уже полученную ссылку.

В `.state/studio-channel.json` хранится идентификатор и название канала, в `.state/studio-jobs.json` — история отправок. Файлы имеют права `0600`; cookies, локальный ключ и секреты сеансов не попадают в историю. Старые параметры API не используются. Не передавайте `.state/token` и `extension/config.js` другим людям.

Документация: [загрузка в Studio](https://support.google.com/youtube/answer/57407), [доступ по ссылке](https://support.google.com/youtube/answer/157177), [разрешение Chrome debugger](https://developer.chrome.com/docs/extensions/reference/api/debugger).

## Что поддерживается

- YouTube, Vimeo и другие источники, поддерживаемые актуальным [yt-dlp](https://github.com/yt-dlp/yt-dlp).
- Прямые MP4/WebM, обычные HLS `.m3u8` и DASH `.mpd`.
- Доступные вам закрытые уроки: встроенный плеер, адрес урока и при необходимости текущая сессия сайта.

Совместимость с каждым учебным сервисом не гарантируется. DRM (Widevine, FairPlay и т. п.) не снимается. Недоступные аккаунту уроки не открываются. Прямые эфиры отклоняются: используйте опубликованную запись. Скачивайте материалы, для которых у вас есть разрешение.

Для новой версии приложения откройте **Обновить VideoDrop.command**. Движок yt-dlp обновляется вместе с зависимостями релиза; выпуск с тем же requirements.txt сохраняет установленный движок. Если подписанная ссылка истекла — снова откройте видео и передайте его из Chrome. VPN, работающий только как расширение Chrome, не меняет сеть локального приложения.

## Локальность

Приложение слушает только `127.0.0.1`. Вызовы защищены локальным ключом, проверкой Host и Origin. Расширение общается с ним напрямую; стороннего сервера VideoDrop нет. Ссылки и cookies не пишутся в журналы. Сессии хранятся в памяти до двух часов и удаляются при завершении процесса. Ключ лежит в `.state/token` и автоматически записывается в `extension/config.js`; не публикуйте эти файлы и не отправляйте папку расширения вместе с ними посторонним. Если ключ меняется, перезагрузите расширение.

## Бесплатные обновления через GitHub — версия 1.4

Готовый комплект для Mac: [последний выпуск](https://github.com/Jeckyllll/videodrop/releases/latest). Скачивайте **VideoDrop-mac.zip**, а не автоматически созданный GitHub архив исходников. Распакуйте в постоянную папку, запустите «Запустить VideoDrop.command», затем один раз подключите папку `extension` в Chrome. Нужен Python 3.10+; для YouTube также Node.js 22+ или Deno. Устанавливать Git или входить в GitHub пользователям не требуется.

На главной странице есть раздел **Обновления VideoDrop**:

- **Обновлять автоматически** включено по умолчанию. Приложение проверяет опубликованные стабильные версии при запуске (с кешем на 6 часов), затем раз в 6 часов, пока работает. После сетевой ошибки — повтор через 30 минут. Проверка кнопкой доступна не чаще раза в 30 секунд.
- **Проверить обновления** и **Установить** позволяют обновиться вручную. Файл «Обновить VideoDrop.command» открывает этот раздел.
- Обновление ждёт завершения поиска, скачивания, подключения канала и отправки на YouTube. После подготовки оно повторно проверяет очередь, блокирует новые задания на время замены и перезапускает локальный сервер. Открытая страница перезагружается при смене версии.
- **Вернуть предыдущую версию** появляется после первого обновления. После отката эта версия не устанавливается повторно автоматически; явная установка остаётся доступной.
- Если изменились файлы расширения, Chrome может потребовать нажать **↻** на карточке VideoDrop в `chrome://extensions`. Новые разрешения подтверждаются в Chrome. Устанавливать папку заново не нужно. Встроенного обновления распакованного расширения с GitHub у Chrome нет.

Перед установкой проверяются SHA-256 архива из API GitHub, список и суммы файлов, версия и репозиторий. Источник доверия — опубликованный выпуск в указанном репозитории GitHub через HTTPS; независимой подписи разработчика здесь нет. Архив распаковывается в отдельную папку, не поверх работающей программы. При смене requirements.txt зависимости готовятся в отдельном окружении, старое сохраняется для отката. Программа проверяет запуск новой версии; при ошибке возвращает прежние файлы. Если питание пропало во время замены, следующий запуск восстанавливает предыдущую версию по журналу.

`.state/`, `.venv/`, `Загрузки/` и персональный `extension/config.js` не входят в выпуск и не заменяются. Каждый пользователь получает собственный локальный ключ, свой вход в Chrome и свой канал YouTube. GitHub получает запросы версии и загрузки программы; видео и входы на сайты туда не отправляются.

### Выпуск следующего обновления

Исходники и релизы: [Jeckyllll/videodrop](https://github.com/Jeckyllll/videodrop). На компьютере разработчика:

1. Измените версию в `version.json`; при изменении расширения — также в `extension/manifest.json`.
2. Проверьте программу: `.venv/bin/python -m unittest discover -s tests -v` и `node --test tests/studio-page.test.cjs tests/studio-driver.test.cjs`.
3. Сохраните изменения в Git и отправьте их в GitHub.
4. Выполните `.venv/bin/python scripts/publish_release.py`. Скрипт собирает чистый пакет из разрешённого списка файлов, создаёт тег текущей версии и публикует GitHub Release. Требуется настроенный `gh` только на компьютере разработчика.

Нельзя включать личные данные в исходники или изменять уже выпущенный тег: для исправлений выпускайте следующий номер версии. Исходники и пакеты публичны. Произвольная новая ветка или коммит не устанавливается у пользователей — только опубликованный стабильный релиз с пакетом VideoDrop.

## Устройство

`app.py` — HTTP-сервер и очередь; `worker.py` — отдельный процесс для yt-dlp/FFmpeg; `web/` — интерфейс без фреймворка; `extension/` — Chrome Manifest V3. FFmpeg поставляется внутри пакета [imageio-ffmpeg](https://github.com/imageio/imageio-ffmpeg); Node.js используется для [YouTube EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS).

`studio.py` — локальная очередь, история и проверка подтверждений; `extension/studio-driver.js` — управление отдельной вкладкой через Chrome debugger; `extension/studio-page.js` — действия и чтение видимого интерфейса Studio; `extension/youtube-ui.js` — общие настройки расширения и локального окна.

Проверки: `.venv/bin/python -m unittest discover -s tests -v`.
Документация Chrome: [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest), [cookies](https://developer.chrome.com/docs/extensions/reference/api/cookies).

## Проверки версии 1.3

Прошли 31 проверка Python и 10 проверок JavaScript. В Chrome проверены новые настройки, сброс удаления и две кнопки открытия для ранее загруженного ролика.

Python: `.venv/bin/python -m unittest discover -s tests -v`.

JavaScript: один раз `npm install --prefix .state/test-deps --no-audit --no-fund --ignore-scripts linkedom`, затем `node --test tests/studio-page.test.cjs tests/studio-driver.test.cjs`. Зависимость нужна только тестам, приложение и расширение работают без неё.

Проверки включают реальные короткие HLS/DASH и преобразование четырёх форматов, безопасность локального API, очередь Chrome, отмену, перезапуск, защиту от дубликатов, проверку доступа и сохранение/удаление локального файла. JavaScript-сценарий проверяется на локальных DOM-данных и подставном Chrome API; это не живая отправка в YouTube.

В настоящем Studio проверены видимые признаки доступа «По ссылке», завершения SD/HD-обработки и имя исходного файла ранее загруженного ролика. Полный автоматический проход нового расширения требует обновления в Chrome и разрешения «Отладчик». Инструмент управления браузером блокирует страницу расширений, поэтому этот шаг выполняет пользователь.
