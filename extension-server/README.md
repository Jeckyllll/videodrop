# VideoDrop — серверное расширение

Локальное приложение, Python, FFmpeg и включённый Mac владельца не нужны. Прямые файлы скачиваются браузером; обработка для отправки на YouTube выполняется на сервере.

1. Распакуйте архив в постоянную папку.
2. В Chrome откройте `chrome://extensions`, включите «Режим разработчика» → «Загрузить распакованное расширение» → выберите эту папку.
3. Откройте VideoDrop и нажмите «Получить код в Telegram». Вставьте личный одноразовый код из бота. Сотруднику сначала нужен допуск владельца в боте.
4. На странице видео откройте расширение. «Скачать на компьютер» запускает прямую загрузку обнаруженного файла, поддерживаемого HLS или открытого видео YouTube. «На YouTube» передаёт выбранный источник на сервер, где можно выбрать формат и качество перед загрузкой в подключённый канал.

Для прямой загрузки не используется хранилище VideoDrop. DASH и защищённые видео пока не поддерживаются. Для загрузки на YouTube требуется подключённый канал; сейчас он не настроен.

Для обработки на сервере доступ к выбранному сайту передаётся по умолчанию; галочку можно отключить. При прямом скачивании cookies на сервер VideoDrop не передаются. При установке или обновлении Chrome запросит однократное разрешение на чтение cookies и доступ ко всем сайтам. Передаются только cookies страницы и выбранного плеера, они хранятся зашифрованными и удаляются после задания или по сроку хранения. DRM не обходится. Если сайт ограничивает серверный IP, наличие доступа не гарантирует скачивание.

«Найти встроенные потоки» включается только по запросу. После обновления страницы запустите видео и снова откройте расширение.

В версии 2.3.0 для обнаруженного HLS-потока открывается отдельная вкладка: в ней можно выбрать доступное разрешение, увидеть оценку размера и сохранить файл MP4 на компьютер. Дорожки объединяются локально без перекодирования. Пока поддерживаются только H.264/AAC и сегменты того же источника; другие кодеки, DRM, сторонние домены потока и DASH могут быть недоступны. Вкладку необходимо держать открытой до завершения. Размер приблизительный. Для обработки используется библиотека Mediabunny 1.62.1 (MPL-2.0); лицензия находится в vendor/MEDIABUNNY-LICENSE, исходный код — https://github.com/Vanilagy/mediabunny/tree/v1.62.1.

В экспериментальной версии 2.4.1 прямое скачивание открытого YouTube-видео получает совместимые H.264 и AAC, предлагает доступные разрешения и их размер, объединяет дорожки локально без повторного сжатия. Код проверен на полном YouTube-видео и Shorts, но ещё не установлен и не проверен в Chrome. Для скрытых браузером перенаправлений добавлена проверка через событие расширения; она пока подтверждена только тестом с имитацией Chrome. YouTube может запросить вход или подтверждение, не предоставить совместимые дорожки или перенаправить поток способом, который браузер не позволяет проверить; в этом случае загрузка остановится. Закрытые YouTube-видео этот способ не поддерживает. Адреса медиапотоков, идентификатор посетителя и видео не отправляются серверу VideoDrop; сведения для журнала описаны ниже.

Версия 2.4.1 пока подготовлена для проверки и не развёрнута. В распакованной установке кнопка перезагружает серверное окно, но не скачивает изменённые файлы расширения; для управляемой установки кнопка дополнительно запускает штатную проверку обновлений Chrome.

## Обновления

Кнопка «Обновить» загружает текущий серверный интерфейс. Основные изменения устанавливаются на сервере один раз для всех сотрудников; архивы менять не нужно. Браузерная оболочка не загружает и не исполняет удалённый код в контексте расширения: серверный интерфейс находится в отдельном изолированном iframe без доступа к Chrome API.

Если изменятся разрешения или сама оболочка, её файлы потребуют замены и нажатия ↻ в `chrome://extensions`. Штатная кнопка Chrome не скачивает обновления распакованного расширения с GitHub. Автоматическое обновление именно оболочки требует Chrome Web Store либо корпоративного управления браузером.

При входе в VideoDrop расширение после завершения прямой загрузки передаёт в журнал название, адрес страницы с удалёнными секретными параметрами и, если известно, разрешение. Видео и cookies не передаются. При недоступности сервера запись повторяется при открытии расширения; другие страницы и история браузера не собираются. Эта функция ещё не проверена в установленном расширении.

### Подготовка управляемых обновлений (не развёрнуто)

Для самостоятельного распространения CRX на macOS и Windows Chrome требует управляемой установки с политикой администратора. Распакованное расширение кнопкой обновления новую версию с сервера не получает. При переходе на подписанный пакет ID расширения может измениться; тогда потребуется однократная установка и повторное подключение. Пользовательские устройства и политики пока не настроены, доставка обновлений в Chrome не проверена.

Сборка для проверки: установить Node 22+ и зависимости `npm ci --prefix scripts`; заранее отдельно создать и безопасно хранить RSA-ключ (права 600, вне репозитория и опубликованных каталогов), затем выполнить `python scripts/build_managed_extension.py --key /путь/к/ключу.pem --output /путь/к/новому-каталогу --base https://адрес/app`. Скрипт создаёт подписанный `VideoDrop-<версия>.crx` и `extension-update.xml` в папке для проверки, ничего не публикует и ключ не создаёт. Для следующих версий необходимо использовать тот же ключ, иначе изменится ID расширения. Нельзя публиковать ключ или включать его в архивы.

Перед развёртыванием необходимы подготовка защищённого хранилища ключа, публикация обоих файлов через HTTPS и проверка политики и обновления на тестовом управляемом устройстве. Подготовленный серверный маршрут выдаёт только разрешённый XML и пакеты с версией в имени. При выпуске сначала публикуется новый пакет, после проверки его доступности обновляется XML; старый пакет сохраняется до завершения проверки. Эти маршруты ещё не развёрнуты и Chrome не настроен.
